# AnviRoute security

AnviRoute's normal workflow is PC-only. It uses an existing API URL and bearer key. The upstream key is hidden during input, stays in memory, is not saved in config, and is removed from the Claude child environment. Only URL, model, and format are saved. Protect the URL too if you consider it sensitive.

The local API binds to 127.0.0.1 and uses a random token per launch. It does not expose the upstream administration API. Public upstream URLs must be HTTPS; redirects are refused to avoid forwarding keys to a different origin. The upstream service and any TLS-terminating tunnel provider remain part of the trust boundary. This does not protect against malware running as your user.

AnviRoute does not add authentication to your existing Kaggle server. An empty key works only if that server permits it. Protect the upstream separately. Browser login flows and custom Cloudflare Access authentication are not supported.

Claude's own settings can override environment variables. Check `/status` before real use. Keep Claude's usual permission checks enabled. Requests are buffered with a 16 MiB response cap; long inference can fail at provider/tunnel timeouts. OpenAI-mode token counts are heuristics, not billing counts.

Report issues privately to the repository owner using GitHub security advisories when available. Never post working credentials or private source in a public issue.

## Legacy KaggleLink transport

The following applies only to the optional older Kaggle-side bridge, not the default AnviRoute launcher.

Use a random shared token generated by `kagglelink token`. Store it in Kaggle Secrets and your local environment. The tunnel exposes only an authenticated job transport; Ollama's administrative API remains on loopback.

The optional discovery registry must be a dedicated private repository. The host uploads URL, model, session ID, and timestamp, never the shared token. Do not make it public later. GitHub and Cloudflare remain part of the trust boundary; Cloudflare terminates TLS. Do not send sensitive workloads if that is inappropriate for you.

Use separate fine-grained GitHub tokens: Contents read/write on Kaggle and Contents read-only on your PC, restricted to the discovery repository. Do not give Kaggle a token for the public source repository. Neither discovery token nor the remote bridge token is inherited by the Claude child process through KaggleLink's environment.

The local bridge binds only to 127.0.0.1 and requires a fresh token per launch. This does not protect against malicious software already running as your user. Claude's existing settings may override environment variables: check `/status` before sending a real prompt.

Limits: eight retained jobs, 16 MiB request and response sizes, 30-minute job retention, and a 300-second upstream socket timeout. Cancellation releases the job but may not immediately interrupt blocked upstream inference. A shared token grants inference access; this is not a multi-user gateway.

For a security issue, contact the repository owner privately using GitHub's security advisory feature when available. Do not post a working exploit with live credentials in a public issue.
